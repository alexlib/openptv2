## Fix 1: Cython `read_targets()` wrapper bug

**File**: `bindings/optv/tracking_framebuf.pyx:226-227`

**Current code**:
```python
num_targets = c_read_targets(tarr, c_string, frame_num)
ret.set(tarr, num_targets, 1)
```

**Problem**: When C returns `-1` (file not found), wrapper creates `TargetArray` with `_num_targets = -1`, causing `SystemError` on `len()`.

**Fix**:
```python
num_targets = c_read_targets(tarr, c_string, frame_num)
if num_targets < 0:
    free(tarr)
    raise FileNotFoundError(
        f"Targets file not found or error reading: {basename}"
    )
ret.set(tarr, num_targets, 1)
```

## Fix 2: Cython `Frame` constructor NULL handling

**File**: `bindings/optv/tracking_framebuf.pyx:265-266`

**Current code**:
```python
def read(Frame self, char *corres_file_base, char *linkage_file_base,
    list target_file_base, int frame_num, prio_file_base):
```

**Problem**: If `read()` is called directly with `None` for `linkage_file_base`, Cython's `None → NULL` conversion for `char *` can cause undefined behavior. The `__init__` guards against this, but `read()` is public and callable directly.

**Fix**: Add validation at the start of `read()`:
```python
def read(Frame self, char *corres_file_base, char *linkage_file_base,
    list target_file_base, int frame_num, prio_file_base):
    if corres_file_base is None or linkage_file_base is None:
        raise ValueError(
            "corres_file_base and linkage_file_base cannot be None"
        )
    # ... rest of method unchanged
```
