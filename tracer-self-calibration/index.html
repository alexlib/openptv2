    Tracer Self-Calibration ("Shaking")¶

    In short

    Refine a plate calibration with real tracked particles in a joint fit of all cameras. The plate is shallow and fixes the depth direction poorly; particles fill the volume.

    Basics: Course page 8. Do it: Tracks break when the set of cameras changes.

    Refine an existing camera calibration using real tracked tracer particles from your flow, instead of only the calibration plate. This is the "modern shaking" step: after a normal plate calibration, particles that were tracked through the actual measurement volume are fed back into a joint bundle adjustment that couples all cameras together.

    Why this exists¶

    A calibration plate is shallow and roughly planar. Reprojection error from plate points alone constrains a camera's pose well in the two directions across the plate, but poorly along the camera's line of sight (depth) — shallow parallax leaves that direction loose. Real tracer particles are distributed through the full depth of the measurement volume, so fitting against them tightens exactly the direction the plate can't see.

    The fit couples every free camera: minimizing the joint reprojection error of shared 3D particle positions (not independent per-camera resection) is what actually reduces cross-camera disagreement — measured as the ray-convergence miss distance (RCM), the median gap between the rays different cameras draw through the same real particle. RCM, not per-camera reprojection RMS, is the diagnostic this step optimizes and reports, because RMS can look fine even when cameras subtly disagree with each other (see calibration-rms-vs-rcm.md).

    Prerequisites¶

    1. A working calibration already exists. This step refines .ori/ .addpar files you already have — it does not calibrate from scratch. Do the normal plate calibration first (detection → manual/sortgrid → raw orientation → fine tuning).
    2. Tracked 3D data exists on real flow images. The routine reads tracked 3D positions and matches them back to per-camera 2D detections, so you need a completed sequence + tracking run on actual flow data (not the calibration plate) before running this step.

    Zarr RunStore input¶

    Tracer self-calibration reads tracked 3D points, correspondences, and per-camera 2D detections directly from the Zarr RunStore (res/run.zarr or run.zarr). Legacy ASCII ptv_is.* files are no longer used.

    Why real-particle filtering and camera focus matter¶

    Naive shaking feeds all matched particles (including ghosts and 2- or 3-camera partial points) into an unweighted bundle adjustment and shakes all free cameras equally. That has two failure modes:

    1. Improving ghosts alongside real particles: when ghost quadruplets enter the fit, the solver pulls the camera orientations toward making the ghost rays meet, legitimizing the ghosts instead of separating them from real particles.
    2. Ignoring which camera causes the ghosts: 72 % of ghosts are 3-camera points where one camera's epipolar search missed the true target because of a sub-pixel calibration offset. Holding the wrong camera fixed — or weighting all cameras equally — fails to focus the correction on the camera causing the mismatch.

    tracer_self_calibrate solves both:

    • Per-camera ghost diagnostics (camera_ghost_diagnostics): measures each camera's 3-camera missing share and its 4-camera reprojection residual on high-confidence real particles, identifying best_cam and worst_cam. Passing hold_cam="auto" automatically holds best_cam as the gauge reference and focuses residual weights (focus_cameras=True) on the cameras with higher badness scores.
    • Real-particle selection & progressive tightening (filter_ghosts=True): prioritizes linked all-camera (n_cams) particles whose ray-convergence ghost probability p_ghost is below a threshold that tightens across iterations (ghost_prob_schedule=(0.25, 0.15, 0.08)), weighting each particle by 1 - p_ghost with a robust soft_l1 loss.
    • Increasing real-vs-ghost separation: as the cameras align on real particles, real particles' RCM drops by ~2× (37.4 -> 17.8 um on L1_d1_c0_k1_n200_s0.08) while true ghosts stay at ~67 um, doubling the ghost-to-real separation ratio (1.76x -> 3.77x, AUC 0.827 -> 0.932).
    • Immediate store update (retriangulate_store): re-triangulating the stored correspondences in res/run.zarr with the shaken calibration cuts trajectory ghost fraction by 34–73 % and lowers velocity error by 5–14 % across the benchmark suite with zero tracking runtime penalty:

    Using it from the GUI¶

    1. Prerequisite: have a Zarr RunStore (res/run.zarr)¶

    Run Sequence and Tracking at least once on your flow images (either from the main openptv2-gui window or via uv run openptv2-batch) so res/run.zarr contains targets/, correspondences/, and linkage/ptv_is.

    2. Open the Calibration GUI & load parameters¶

    1. From the main openptv2-gui window, open Calibration → Create calibration, or launch the calibration dialog directly from the terminal: 
      uv run python -m openptv2.gui.calibration_gui path/to/parameters_Run1.yaml
    2. Click Load/Show Images (top button on the left panel) — required before any other button, including Tracer self-cal, becomes active.

    3. Configure the Shaking Parameters¶

    Click Edit calibration parameters → open the "Shaking calibration parameters" tab (Group6):

    Field Recommended Value Meaning & Notes
    shaking_first_frame / shaking_last_frame e.g. 1 to 200 Tracked frame range in res/run.zarr to pull particles from
    shaking_max_num_frames 20 – 50 Subsample down to this many frames (evenly spaced) so the fit stays fast on long sequences
    shaking_max_num_points 400 Cap on high-confidence real particles used in the joint fit
    shaking_tol_px 2.0 Pixel tolerance for matching a tracked 3D point's reprojection to a 2D detection in each camera
    shaking_hold_cam (0=auto, 1..N=cam) 0 (auto) 0 (default) runs camera_ghost_diagnostics, holds the cleanest camera (best_cam) fixed as the gauge reference, and focuses the shake on the camera causing the most ghosts (worst_cam). Set 1..N to manually hold a specific camera

    Click OK to save the dialog settings.

    4. Click "Tracer self-cal"¶

    Click Tracer self-cal (left panel, below "Suggest eps0"). It runs 3 progressive iterations (ghost_prob_schedule = (0.25, 0.15, 0.08)), printing progress to the terminal and updating the GUI status bar:

    5. Automatic .ori backup, write, and Zarr store re-triangulation¶

    The refined calibration is accepted only if RCM_after < RCM_before. When it improves, the GUI automatically: 1. Backs up your current .ori and .addpar files (*.bck), 2. Writes the refined .ori and .addpar files to disk for every free camera, and 3. Runs retriangulate_store(...) on res/run.zarr so the stored 3D correspondences are immediately updated with the shaken calibration (ready to re-run Track right away).

    By default (filter_ghosts=True), tracer_self_calibrate prioritizes linked 4-camera (all-camera) real particles with low ghost probability (p_ghost) and progressively tightens the p_ghost threshold across iterations.

    What actually happens (algorithm)¶

    1. Load tracked 3D positions, correspondences, linkage, and per-camera 2D detections from the Zarr RunStore (res/run.zarr).
    2. Diagnose cameras (camera_ghost_diagnostics): measure each camera's 3-camera missing share and 4-camera reprojection residual on high-confidence real particles to identify best_cam and worst_cam.
    3. Select real particles: filter out ghost candidates using ray-convergence ghost probability (p_ghost <= q_thresh), prioritizing linked all-camera particles and weighting each particle by 1 - p_ghost.
    4. Fit: one coupled least-squares bundle adjustment (scipy.optimize. least_squares, sparse Jacobian, soft_l1 loss) refines every free camera's exterior orientation (position + scaled mrad angles) and the real particles' 3D positions together, including the held reference camera's 2D observations in the residual and focusing camera weights on higher-badness cameras.
    5. Accept or reject & tighten: evaluate the median RCM on the reference real particle set and record the ghost-to-real RCM separation ratio. Tighten q_thresh (ghost_prob_schedule) on the next iteration and stop when RCM plateaus.

    After running it¶

    • Call retriangulate_store(base, new_cals, cpar) to update the 3D correspondence positions in res/run.zarr immediately, or re-run sequence + tracking (recorrespond + track_store) with the refined calibration.
    • Cross-check the improvement with the visualize-calibration skill or openptv2.calibration_diagnostics (sight-line angle, cross-camera symmetry, cross-camera RCM).

    Troubleshooting¶

    Symptom Likely cause Try
    "no Zarr RunStore found (run sequence + tracking first)" Sequence+tracking has not been run yet (no res/run.zarr) Run sequence + tracking first so res/run.zarr holds correspondences and linkage
    "only N multi-cam tracer particles" (skipped, N < 10) Too few particles matched in ≥2 cameras for the configured frames Widen the frame range, loosen shaking_tol_px, or check that detection/tracking found particles in those frames
    RCM doesn't improve on iteration 1 Starting calibration is already good for this data, or tol_px is too tight/loose Try hold_cam="auto", adjust tol_px, or accept that this dataset doesn't need further refinement
