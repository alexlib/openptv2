    Plan: zarr-only v0.5.6¶

    Date: 2026-08-26 Branch: ci-debug/zero-links → PR #33 Goal: v0.5.6 ships with Zarr RunStore as the only runtime data path. ASCII (*_targets, rt_is.*, ptv_is.*, added.*) survives ONLY as an interchange/export format behind openptv2.storage.legacy (import/export) and as calibration-GUI target files where explicitly documented.

    Baseline audit (2026-08-26): see "ASCII audit" in PR #33 discussion; the stragglers are listed per phase below.

    Phase 1 — HIGH severity: make every runtime path store-native¶

    # Item File(s) Change
    1.1 myptv 2D tracking plugin is ASCII-bound plugins/myptv_2d_tracking.py:250,326 thread store= through Frame reads and frame.write, exactly like myptv_3d_tracking.py
    1.2 autocalibration prefers ASCII, hardcodes res/run.zarr autocalibration.py:_load_tracer_frame_data store-FIRST (ASCII only if no store), resolve via find_existing_store; read detections through the store too
    1.3 tracking recommender reads rt_is files only tracking_recommender.py, cli.py recommend accept experiment dir OR store: use find_existing_store when present, else legacy rt_is glob (reads via read_path_frame)
    1.4 3D-positions viz broken for pure-store runs gui/plot_3d_positions.py:399,432, gui/pyptv_gui.py:899 add store branch: build positions array from store.read_correspondences(frame); keep rt_is file fallback
    1.5 rt_is notebook helper gui/visualize_rt_is_nb.py same store branch

    Phase 2 — MEDIUM: fixtures & datasets become stores¶

    # Item Detail
    2.1 conversion script scripts/convert_fixtures_to_zarr.py: for every test_data/* dataset with res_orig/img targets but no store, ingest into <root>/run.zarr (fixture location, survives test copies that ignore res*) via import_run-equivalent writes from res_orig ONLY — never from a working-copy res/ (see 2026-08-25 parity incident)
    2.2 datasets to convert test_data/track (from res_orig + img_orig, incl. ptv_is/added+prio), test_data/test_cavity (done), others as discovered by script scan
    2.3 gitignore policy committed ASCII stays only where a consumer needs it on CI: cal targets + cavity img targets (dumbbell tool), track res_orig/img_orig (legacy compat tests). Everything else untracked as today
    2.4 benchmarking writer benchmarking/datawriter.py gains write_store() producing a native RunStore dataset; ASCII writer kept for golden-file comparisons

    Phase 3 — tests¶

    3a. Regression (correctness under migration)¶

    # Test Asserts
    3.1 store↔ASCII round-trip parity export_run(store→ascii) == original ascii bytes for targets/rt_is/ptv_is/added (extends test_convert_legacy_to_zarr.py)
    3.2 tracking parity store vs ascii exists (test_parallel_tracking); extend to track dataset once converted
    3.3 plugin parity run myptv_2d/3d + proptv twice on same input: once store-fed, once ASCII-fed → identical npart/nlinks/linkage arrays

    3b. Fast parallel I/O (new)¶

    # Test Asserts
    3.4 concurrent writers N threads write distinct frames (targets+correspondences+linkage) to one RunStore; all frames readable back bit-exact afterwards
    3.5 concurrent readers/writers readers enumerate frames while writers append; no torn reads (frame either absent or complete)
    3.6 parallel chunked tracking I/O _InMemoryLinkageStore merge produces identical linkage to sequential pass (already partially covered; pin it as regression)

    Runtime budget for 3b: < 30 s total.

    3c. CI slimming¶

    CI's job is to block wrong code cheaply, not to re-run the whole suite:

    • Introduce pytest marker ci (registered in pyproject).
    • Mark the minimal set with pytestmark = pytest.mark.ci:
    • storage: test_run_store.py, test_convert_legacy_to_zarr.py, new test_store_parallel_io.py (3.4/3.5), new test_legacy_roundtrip.py (3.1)
    • tracking: test_parallel_tracking.py, test_trackcorr_store_only.py, plugin parity test (3.3)
    • correspondences: test_parallel_correspondences.py
    • calibration: test_standalone_dumbbell_calibration_cycle.py
    • sanity: test_self_check.py
    • .github/workflows/ci.yml: uv run pytest -m ci -q (target: < 5 min/job) instead of -m "not slow".
    • Everything else keeps running locally / nightly via scripts/run_regression_tests.py --tier1.

    Phase 4 — release mechanics¶

    • version bump 0.5.5 → 0.5.6 in pyproject.toml.
    • CHANGELOG entry summarizing: zarr-only runtime, ASCII = interchange only, parallel-I/O hardening, CI split (ci marker vs full local suite).

    Execution order¶

    1.1 → 1.2 → 2.1/2.2 → 3.x tests → 1.3 → 1.4/1.5 → 2.4 → CI cutover → bump. Each item lands with its own commit; CI must stay green after each push.
